## 실행과 연결

| 항목 | 내용 |
|---|---|
| 소속 이미지 | `inventory-service` |
| 실행 역할 | 백그라운드 Worker |
| 배포 단위 | `Deployment`: `inventory-consumer` |
| 업무용 Service | 불필요: 이 모듈이 Kafka·DB로 연결한다 |
| 연결 대상 | 재고 DB·Kafka |
| 입력 | Kafka 재고 확보·반환 요청 |
| 출력 | 재고 DB에 결과 Outbox를 저장한다. Kafka 결과 전송은 재고 결과 발행 모듈이 담당한다. |

## 구현할 기능

| 기능 | 처리 내용 |
|---|---|
| 확보 요청 | 중복 여부와 주문 가능 수량을 확인하고 주문별 예약을 생성한다. |
| 여러 상품 확보 | 모든 상품을 확보할 수 있을 때만 예약한다. 일부 상품만 예약하지 않는다. |
| 확보 실패 | 재고를 변경하지 않고 실패 사유·처리 기록·결과 Outbox를 저장한다. |
| 반환 요청 | 해당 주문의 예약을 해제하고 결과 Outbox를 저장한다. |
| 일관성·소비 위치 | 수량 변경·처리 기록·Outbox를 함께 저장하고 성공 후 Kafka 소비 위치를 기록한다. |

## 실패·복구 설계

동시 주문·중복 이벤트·DB 충돌을 구분한다. 일시적 DB 장애를 재고 부족으로 판단하지 않는다. 예약 없는 반환 요청의 처리 정책을 정한다.

## Kubernetes 파일 계획

다음 이름의 파일을 설계 후 k8s 폴더에 작성한다. 현재 파일을 생성하거나 설정값을 확정한 상태는 아니다.

- `deployment.yaml`
- `configmap.yaml`
- `serviceaccount.yaml`

인증정보는 Secret 참조 방식을 정한 뒤 연결한다. 실제 비밀값을 저장소에 넣지 않는다. 복제 수·Probe·requests/limits·종료 처리·배치·확장·통신 정책은 이 모듈의 설계 단계에서 정한다. Worker의 모니터링용 Service가 필요하면 업무용 Service와 구분해 추가한다.

## 구현 전 정할 것

- 요청·응답 또는 이벤트 구조와 오류 처리 기준.
- DB 테이블·트랜잭션·중복 방지 방식.
- 연결 설정과 비밀·권한 전달 방식.
- 실행 명령·상태 점검·종료 방식.
- 정상·배포·장애·복구 검증 항목.

## 실행·검증 방법

구현 후 실제 명령과 확인 결과를 기록한다. 현재 실행 가능한 프로그램과 적용 가능한 YAML은 없다.
