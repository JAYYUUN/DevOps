## 실행과 연결

| 항목 | 내용 |
|---|---|
| 소속 이미지 | `product-service` |
| 실행 역할 | HTTP API |
| 배포 단위 | `Deployment`: `product-api` |
| 업무용 Service | 필요 |
| 연결 대상 | 상품 DB·Redis |
| 입력 | HTTP 상품 조회·관리 요청 |
| 출력 | 상품 정보 또는 처리 결과를 HTTP로 반환한다. |

## 구현할 기능

| 기능 | 처리 내용 |
|---|---|
| 상품 등록 | 상품명·설명·가격을 검증하고 상품 DB에 저장한다. |
| 상품 수정·판매 중지 | 상품 DB 변경 후 Redis의 해당 상품 캐시를 삭제한다. |
| 상품 상세 조회 | Redis를 먼저 확인하고, 없으면 상품 DB에서 읽어 만료시간과 함께 캐시에 저장한다. |
| 상품 목록 조회 | 상품 DB에서 조건별·페이지별로 조회한다. |
| 주문용 정보 조회 | 주문 API의 요청에 대해 캐시를 거치지 않고 원본 가격·판매 상태를 조회한다. |

## 실패·복구 설계

캐시 조회 실패 시 DB 조회로 전환한다. 캐시 저장 실패가 원본 조회 응답을 실패시키지 않도록 한다. 캐시 삭제 실패 재시도와 원본 DB 보호 기준을 설계한다.

## Kubernetes 파일 계획

다음 이름의 파일을 설계 후 k8s 폴더에 작성한다. 현재 파일을 생성하거나 설정값을 확정한 상태는 아니다.

- `deployment.yaml`
- `service.yaml`
- `configmap.yaml`
- `serviceaccount.yaml`

인증정보는 Secret 참조 방식을 정한 뒤 연결한다. 실제 비밀값을 저장소에 넣지 않는다. 복제 수·Probe·requests/limits·종료 처리·배치·확장·통신 정책은 이 모듈의 설계 단계에서 정한다. Worker의 모니터링용 Service가 필요하면 업무용 Service와 구분해 추가한다.

## 구현 전 정할 것

- 요청·응답 또는 이벤트 구조와 오류 처리 기준.
- DB 테이블·트랜잭션·중복 방지 방식.
- 연결 설정과 비밀·권한 전달 방식.
- 실행 명령·상태 점검·종료 방식.
- 정상·배포·장애·복구 검증 항목.

## 실행·검증 방법

구현 후 실제 명령과 확인 결과를 기록한다. 현재 실행 가능한 프로그램과 적용 가능한 YAML은 없다.
