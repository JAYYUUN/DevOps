# 배포 설정

## 로컬 실행

Python 3.12와 Docker Compose가 필요하다. 프로젝트 루트에서 실행한다.

```bash
cp .env.example .env
# .env의 DB_PASSWORD, DB_ROOT_PASSWORD, ADMIN_API_KEY, INTERNAL_API_KEY를 변경한다.
# 로컬 Compose DB 비밀번호는 URL에 바로 들어가므로 충분히 긴 무작위 hex 값을 사용한다.
docker compose up --build -d
curl http://127.0.0.1:8000/health/ready
```

Compose는 MariaDB·Redis를 띄우고 DB가 준비되면 초기 마이그레이션을 적용한 다음 API를 실행한다. Redis·DB 포트는 호스트에 공개하지 않는다. 개발용 Redis는 컨테이너 내부망에서 인증 없이 사용한다. 운영 환경에서는 인증된 별도 Redis를 사용한다.

Swagger UI: http://127.0.0.1:8000/docs . Authorize에서 관리자 또는 내부 API 키를 입력한다. 사용자 조회는 인증 없이 제공한다. 가격은 JSON 응답에서 정확도를 위해 문자열로 반환한다.

## 기존 DB·Redis에 직접 연결

.env의 DATABASE_URL과 REDIS_URL을 실제 주소로 설정한다. URL의 사용자명·비밀번호에 특수문자가 있으면 URL 인코딩한다.

```bash
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
export PYTHONPATH=src
python -m app.migrate
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

초기 DB와 사용자는 사전에 생성해야 한다. 마이그레이션 계정에는 DDL 권한, API 계정에는 상품 테이블 DML 권한이 필요하다. 현재 예시는 같은 접속 설정을 사용하며 운영에서는 Job과 API의 Secret을 분리할 수 있다.

## 코드와 이미지

Dockerfile은 src 전체와 의존성을 하나의 이미지에 포함한다. main.py가 모든 라우터를 연결하고 Uvicorn 프로세스 하나로 실행한다. 관리자와 내부 호출은 서로 다른 X-API-Key로 보호한다. 키는 HTTPS 또는 신뢰하는 내부망에서 전달한다. 향후 사용자 인증 체계가 정해지면 교체할 수 있다.

## Kubernetes

동일한 네임스페이스에 배포한다. 외부 MariaDB·Redis는 사전 준비한다. deployment.yaml과 migration-job.yaml의 YOUR_REGISTRY를 실제 이미지 주소로 바꾼다.

```bash
docker build -t YOUR_REGISTRY/product-api:1.0.0 .
docker push YOUR_REGISTRY/product-api:1.0.0
cp k8s/secret.example.yaml k8s/secret.yaml
# secret.yaml의 URL과 API 키를 실제 값으로 변경한다.
kubectl apply -f k8s/configmap.yaml
kubectl apply -f k8s/secret.yaml
kubectl apply -f k8s/migration-job.yaml
kubectl wait --for=condition=complete job/product-api-migrate-v1 --timeout=120s
kubectl apply -f k8s/deployment.yaml
kubectl apply -f k8s/service.yaml
kubectl rollout status deployment/product-api
```

예시 Secret까지 적용되지 않도록 `kubectl apply -f k8s/`는 사용하지 않는다. 마이그레이션은 한 번에 하나만 실행하고 실패하면 로그를 확인한다. 미래 스키마 변경은 새 버전의 마이그레이션으로 추가해야 하며 create_all은 기존 컬럼을 변경하지 않는다.

Service는 ClusterIP이며 Ingress는 포함하지 않는다. 운영 도메인·TLS·네트워크 접근 제한은 클러스터 정책에 맞춰 추가한다. startup/liveness는 프로세스 응답, readiness는 DB 연결을 확인한다. Redis 실패는 준비 상태를 실패시키지 않는다.

## 파일 분담

| 파일 | 역할 |
|---|---|
| deployment.yaml | Pod 2개·환경변수·자원·probe |
| service.yaml | 내부 접근 주소 |
| configmap.yaml | 캐시 TTL |
| secret.example.yaml | DB/Redis URL·서로 다른 API 키의 예시 |
| migration-job.yaml | API 실행과 분리된 최초 테이블 생성 |
| .env.example | 로컬 실행과 Compose 설정 예시 |
