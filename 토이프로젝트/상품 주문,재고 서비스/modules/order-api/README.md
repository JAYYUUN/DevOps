|---|---|

| 업무용 Service | 필요 |
| 연결 대상 | 주문 DB·상품 API |

| 출력 | 접수 시 주문 ID와 처리 중 상태를 반환한다. Kafka 직접 전송은 주문 이벤트 발행 모듈이 담당한다. |

## 구현할 기능

| 기능 | 처리 내용 |
|---|---|
| 주문 접수 | 상품 API로 원본 가격·판매 상태를 확인하고 주문 수량과 금액을 검증한다. |
| 접수 저장 | 주문·주문 항목·재고 확보 요청 Outbox를 주문 DB에 같은 트랜잭션으로 저장한다. |
| 주문 조회 | 본인의 주문 목록·상태·실패 사유를 주문 DB에서 조회한다. |
| 취소 접수 | 소유자와 상태를 확인하고 취소 처리 중 상태·재고 반환 요청 Outbox를 함께 저장한다. |
| 중복·관리자 조회 | 중복 요청 식별값을 검증하고, 관리자에게 실패·미완료 주문 조회를 제공한다. |

## 실패·복구 설계

같은 요청 식별값으로 다른 내용을 보낸 경우 거절한다. 상품 확인·주문 저장 실패를 접수 성공으로 반환하지 않는다. 취소 가능 상태는 구현 전 확정한다.

## Kubernetes 파일 계획

다음 이름의 파일을 설계 후 k8s 폴더에 작성한다. 현재 파일을 생성하거나 설정값을 확정한 상태는 아니다.

- `deployment.yaml`
- `service.yaml`
- `configmap.yaml`
- `serviceaccount.yaml`

인증정보는 Secret 참조 방식을 정한 뒤 연결한다. 실제 비밀값을 저장소에 넣지 않는다. 복제 수·Probe·requests/limits·종료 처리·배치·확장·통신 정책은 이 모듈의 설계 단계에서 정한다. Worker의 모니터링용 Service가 필요하면 업무용 Service와 구분해 추가한다.

## 구현 전 정할 것

- 요청·응답 또는 이벤트 구조와 오류 처리 기준.
- DB 테이블·트랜잭션·중복 방지 방식.
- 연결 설정과 비밀·권한 전달 방식.
- 실행 명령·상태 점검·종료 방식.
- 정상·배포·장애·복구 검증 항목.

## 실행·검증 방법

구현 후 실제 명령과 확인 결과를 기록한다. 현재 실행 가능한 프로그램과 적용 가능한 YAML은 없다.
