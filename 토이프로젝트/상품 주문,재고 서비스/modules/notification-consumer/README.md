## 실행과 연결

| 항목 | 내용 |
|---|---|
| 소속 이미지 | `notification-service` |
| 실행 역할 | 백그라운드 Worker |
| 배포 단위 | `Deployment`: `notification-consumer` |
| 업무용 Service | 불필요: 이 모듈이 Kafka·DB로 연결한다 |
| 연결 대상 | 알림 DB·Kafka |
| 입력 | Kafka 주문 확정·실패·취소 완료 결과 |
| 출력 | 알림 DB에 서비스 내 알림을 저장한다. 사용자는 알림 API를 통해 조회한다. |

## 구현할 기능

| 기능 | 처리 내용 |
|---|---|
| 주문 확정 | 주문 확정 알림을 생성한다. |
| 주문 실패 | 사용자에게 보여줄 실패 사유를 포함한 알림을 생성한다. |
| 주문 취소 완료 | 취소 완료 알림을 생성한다. |
| 중복 방지 | 알림과 이벤트 처리 기록을 같은 DB 트랜잭션으로 저장한다. |
| 소비 위치 반영 | 알림 DB 저장 성공 후 Kafka 소비 위치를 기록한다. |

## 실패·복구 설계

알림 저장 실패 시 재시도한다. DB 저장 후 소비 위치 기록 실패로 재수신해도 알림을 중복 생성하지 않는다. 알림 지연을 주문 실패로 처리하지 않는다.

## Kubernetes 파일 계획

다음 이름의 파일을 설계 후 k8s 폴더에 작성한다. 현재 파일을 생성하거나 설정값을 확정한 상태는 아니다.

- `deployment.yaml`
- `configmap.yaml`
- `serviceaccount.yaml`

인증정보는 Secret 참조 방식을 정한 뒤 연결한다. 실제 비밀값을 저장소에 넣지 않는다. 복제 수·Probe·requests/limits·종료 처리·배치·확장·통신 정책은 이 모듈의 설계 단계에서 정한다. Worker의 모니터링용 Service가 필요하면 업무용 Service와 구분해 추가한다.

## 구현 전 정할 것

- 요청·응답 또는 이벤트 구조와 오류 처리 기준.
- DB 테이블·트랜잭션·중복 방지 방식.
- 연결 설정과 비밀·권한 전달 방식.
- 실행 명령·상태 점검·종료 방식.
- 정상·배포·장애·복구 검증 항목.

## 실행·검증 방법

구현 후 실제 명령과 확인 결과를 기록한다. 현재 실행 가능한 프로그램과 적용 가능한 YAML은 없다.
