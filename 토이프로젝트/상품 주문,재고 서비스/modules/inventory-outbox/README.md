## 실행과 연결

| 항목 | 내용 |
|---|---|
| 소속 이미지 | `inventory-service` |
| 실행 역할 | 백그라운드 Worker |
| 배포 단위 | `Deployment`: `inventory-outbox` |
| 업무용 Service | 불필요: 이 모듈이 Kafka·DB로 연결한다 |
| 연결 대상 | 재고 DB·Kafka |
| 입력 | 재고 DB의 미발행 결과 Outbox |
| 출력 | Kafka에 재고 처리 결과를 보내고 재고 DB에 전송 상태를 기록한다. |

## 구현할 기능

| 기능 | 처리 내용 |
|---|---|
| 결과 조회 | 미발행 결과와 재시도 시각을 조회한다. |
| 작업 확보 | 여러 실행 인스턴스 간 처리 대상을 점유한다. |
| 결과 전송 | 확보 성공·실패 및 반환 성공·실패 결과를 Kafka로 전송한다. |
| 발행 기록 | 전송 확인 후 재고 DB에 발행 완료를 기록한다. |
| 재시도 | 오류·횟수·다음 시도 시각을 저장하고 중단된 작업을 회수한다. |

## 실패·복구 설계

중복 전송 가능성을 전제로 주문 결과 처리 모듈에서 중복 반영을 방지한다. 반복 실패한 결과를 삭제하지 않고 확인 대상으로 남긴다.

## Kubernetes 파일 계획

다음 이름의 파일을 설계 후 k8s 폴더에 작성한다. 현재 파일을 생성하거나 설정값을 확정한 상태는 아니다.

- `deployment.yaml`
- `configmap.yaml`
- `serviceaccount.yaml`

인증정보는 Secret 참조 방식을 정한 뒤 연결한다. 실제 비밀값을 저장소에 넣지 않는다. 복제 수·Probe·requests/limits·종료 처리·배치·확장·통신 정책은 이 모듈의 설계 단계에서 정한다. Worker의 모니터링용 Service가 필요하면 업무용 Service와 구분해 추가한다.

## 구현 전 정할 것

- 요청·응답 또는 이벤트 구조와 오류 처리 기준.
- DB 테이블·트랜잭션·중복 방지 방식.
- 연결 설정과 비밀·권한 전달 방식.
- 실행 명령·상태 점검·종료 방식.
- 정상·배포·장애·복구 검증 항목.

## 실행·검증 방법

구현 후 실제 명령과 확인 결과를 기록한다. 현재 실행 가능한 프로그램과 적용 가능한 YAML은 없다.
