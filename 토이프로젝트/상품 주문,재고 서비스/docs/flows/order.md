# 첫 번째 구현 흐름: 주문과 재고

## 목표

아래 흐름 하나를 실제로 실행하고 테스트한다.

```text
주문 접수
  → 재고 확보 요청
  → 재고 확보 처리
  → 처리 결과 전달
  → 주문 상태 변경
```

첫 구현에서는 이 흐름을 완성하는 데 필요한 구성만 선택한다. 특정 메시지 브로커, 데이터베이스, Outbox, Kubernetes를 미리 전제하지 않는다.

## 처리 단계

1. 주문 서비스가 주문 요청을 받고 처리 중인 주문을 기록한다.
2. 주문 서비스가 해당 주문의 재고 확보 요청을 재고 서비스에 전달한다.
3. 재고 서비스가 요청을 처리하고 확보 성공 또는 실패 결과를 만든다.
4. 주문 서비스가 결과를 받아 주문 상태를 확정 또는 실패로 갱신한다.
5. 테스트에서 주문 요청부터 최종 상태까지 연결된 결과를 확인한다.

## 첫 버전의 완료 기준

- 성공 요청은 재고 확보 성공과 주문 확정 상태로 이어진다.
- 재고 부족은 확보 실패와 주문 실패 상태로 이어진다.
- 재고 확보 요청을 반복해도 같은 주문의 재고가 두 번 차감되지 않는다.
- 서비스 간 요청과 결과를 추적할 수 있다.
- 자동 테스트로 성공·실패 흐름을 검증한다.

## 이후 확장

1. 중복 요청과 중복 결과 처리
2. 일시적 오류의 재시도와 복구
3. 취소 및 예약 해제
4. 알림 등 새로운 서비스
5. 컨테이너화와 Kubernetes 배포

각 단계는 앞 단계가 동작하는 것을 확인한 뒤 추가한다.
