|---|---|---|

## 설계와 구현 단계

| 단계 | 완료 기준 |
|---|---|
| 요구사항 | 첫 사용자 흐름·범위·정상 및 실패 기대 결과를 합의 |
| 논리 설계 | 책임·데이터 소유권·통신·주요 실패 흐름 설명 가능 |
| 배치 설계 | EKS 안팎의 위치·권한·장애 영역·비용 판단 |
| 구현 설계 | 각 Kubernetes 자원과 설정을 선택한 이유 설명 가능 |
| 구현·검증 | 실제 결과를 기대 동작과 비교하고 한계 기록 |

논리 설계 이후 필요해지면 `implementation/aws/README.md`, `implementation/kubernetes/README.md`, `operations/README.md`를 이 docs 폴더 아래 추가합니다. 현재는 이 경로들을 미리 생성하지 않습니다.

## 갱신 규칙

1. 해당 내용을 담당하는 문서에 먼저 기록합니다.
2. 선택이 바뀌면 decisions에 이유와 영향을 남깁니다.
3. progress에 완료·미결 내용과 다음 행동 하나를 기록합니다.
4. 하위 문서를 추가하면 이 안내와 관련 상위 문서에 상대 경로 링크를 추가합니다.

문서의 상태는 ‘제안’, ‘확정’, ‘보류’, ‘대체’로 표시합니다. 이전 대화에서 등장했다는 이유만으로 확정으로 올리지 않습니다.
